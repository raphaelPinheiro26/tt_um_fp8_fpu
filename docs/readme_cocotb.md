# Module-level cocotb testbenches

These are **Python/cocotb ports of the legacy Verilog testbenches** in `sim/`.
Tiny Tapeout runs cocotb, so the whole verification stack is now Python-based:
the official top-level suite lives in [`../../test/`](../../test/), and these
per-module suites reproduce the block-level checks that the `sim/*.v`
testbenches used to do.

They do **not** run in the Tiny Tapeout flow (only `test/` does); they are here
for local block-level debugging and regression.

| Directory     | DUT (`src/`)             | Legacy TB it replaces                  |
|---------------|--------------------------|----------------------------------------|
| `handshake/`  | `fp8_handshake_reg`      | `tb_handshake_elastic.v`               |
| `pipeline/`   | `fp8_elastic_pipeline`   | `tb_fp8_golden.v`, `tb_fp8_elastic.v`, `tb_fp8_elastic_stream.v` |
| `unit/`       | `tiny_fp8_unit`          | `tb_fp8_unit.v`                        |
| `controller/` | `fp8_controller`         | `tb_fp8_controller.v`                  |

`fp8_vectors.py` is a shared helper that locates `Golden_model/vectors.hex`
(generated by `Golden_model/gen_vectors_math.py`) and returns the golden
`(A, B, opcode, rm, result, flags, exceptions)` rows.

## What each suite checks

- **handshake** — pushes an incrementing counter through the elastic
  skid-buffer with random input bubbles and output back-pressure and asserts
  the output is byte-exact and **in order** (no loss / duplication / reorder),
  plus a `flush` test. This is the exact property the buffer was fixed for
  (see the header of `src/fp8_handshake_reg.v`).
- **pipeline** — directed NaN/Inf/zero/subnormal cases, then replays golden
  vectors through the 4-stage datapath at full throughput and again with random
  bubbles + back-pressure, self-checking every `result/flags/exceptions` in
  order.
- **unit** — same golden replay through `controller + pipeline`, additionally
  checking that the destination-register (`rd`) tag returns in order.
- **controller** — drives the issue interface while a **Python model of the
  pipeline** returns results with latency; checks in-order writeback with the
  right `rd`, the `issue_ready` gating when the rd FIFO is full, and `flush`.

## Running

Requires `iverilog` and `cocotb`, and a generated `Golden_model/vectors.hex`:

```bash
# once, from the repo root:
python3 Golden_model/gen_vectors_math.py        # writes Golden_model/vectors.hex

# then run any suite:
cd sim/cocotb/pipeline   && make
cd sim/cocotb/unit       && make
cd sim/cocotb/handshake  && make
cd sim/cocotb/controller && make
```

Useful environment knobs (vector-driven suites):

| Variable   | Default | Meaning                                         |
|------------|---------|-------------------------------------------------|
| `FP8_NVEC` | 4000    | golden vectors replayed at full throughput      |
| `FP8_NBP`  | 1500    | golden vectors for the back-pressure run        |
| `FP8_N`    | 4000    | items pushed through the handshake buffer        |
| `FP8_SEED` | 1       | RNG seed for the random bubbles / back-pressure  |
| `FP8_VEC`  | (auto)  | explicit path to `vectors.hex`                   |
